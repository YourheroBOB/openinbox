## 建議驗收條件

1. 所有新測試使用 `tempfile`／`tmp_path` 與虛構資料，不連正式服務。
2. 測試憑證只用 `FAKE_VALUE_FOR_TEST` 這類假值；不寫入任何真實 token、金鑰、密碼或郵件內文。
3. 破壞性 API 變更需先採向後相容；若改變 `/api/agents/*` 回應形狀，需在文件與 SUMMARY 告知 BOB。
4. 每個修補都要能對應到本文件的問題 ID。
5. 文件更新以實際程式行為為準，不提前宣稱尚未完成的能力。
