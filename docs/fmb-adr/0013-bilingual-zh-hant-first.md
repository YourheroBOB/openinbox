# ADR 0013：雙語（繁中優先）與字串規則

- 狀態：已接受（回溯整理）
- 相關程式：`ui/index.html`（核心字串）、`ui/modules/*.js`（每個模組自帶字串表）、`server/features/*.py`（`LABELS`、`lang`、`req.lang_zh()`）、`skills/*.md`、`CONTRIBUTING.md`

## 背景

主要使用者讀繁體中文，但這個 repo 是公開的，也需要英文。
在平行開發的前提下（ADR 0004），如果所有字串都集中在一個檔案，每條分支都會撞在一起。

## 決策

1. 每個 UI 模組**自帶** `zh`／`en` 兩份字串表，用 `document.documentElement.lang` 決定；面板核心的字串留在 `ui/index.html`。
2. 後端用 `lang` 參數或 `req.lang_zh()` 決定回傳語言；AI 功能的 `LABELS` 也是雙語。
3. **繁體中文為主、英文並列**；技能 markdown 是「繁中在前、英文在後」。**禁止簡體中文。**
4. 使用者可見的**錯誤、fallback、空狀態**也要雙語，不能只翻譯標題。
5. 語言可由網址參數切換；深連結（`#view=…`）與語言要能共存。
6. 切換語言時，模組要自己重新標字（核心會覆寫某些節點，見陷阱），不能只依賴重新載入頁面。

## 取捨

**我們放棄**

- 集中式翻譯檔與字串 key 檢查：沒有工具會告訴你缺了哪一句。
- 某些字串的一次性翻譯（同一句話可能在多個模組各寫一次）。

**我們得到**

- 模組可以獨立完成、獨立合併；一個模組壞掉不會讓整份翻譯消失。
- 每個功能的中英文語感可以自己調整。

**已知代價**

- 容易漏翻；審查要靠人眼與測試斷言（很多測試會直接檢查字串存在）。
- 同一概念在不同模組可能用詞不一致。

## 後果

- 新增任何使用者可見文字：**同時**寫 `zh` 與 `en`，缺一邊視為 bug。
- 不要引入簡體字；不要為了省事把中文寫進英文欄位。
- 後端回傳的錯誤訊息也要能雙語（`refuse(req.lang_zh())` 這類做法）。
- 文件與範例以繁中為主，識別字保留英文，方便 grep。
