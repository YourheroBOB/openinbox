# ADR 0008：唯讀連接器與憑證只從環境變數

- 狀態：已接受（回溯整理）
- 相關程式：`server/features/imap.py`、`server/features/providers.py`、`server/yhbmail.py`（`DRIVERS`／`LAST_SYNC`）、`tests/_tpi_imap_fake.py`、`README.md`（真信箱一節）

## 背景

使用者會想把真的信箱接上來（Gmail、Outlook、iCloud、其他 IMAP）。
一旦這個工具會**改動伺服器端狀態**（標已讀、搬資料夾、刪信），任何 bug 都會變成使用者的災難；
而憑證如果被寫進設定檔，就會跟著備份、截圖、PR 一起外流。

## 決策

1. **所有郵件連接器都是唯讀的。**
   - IMAP：以 `EXAMINE` 開信箱、`BODY.PEEK` 取信，不在伺服器上留下任何變更（連已讀旗標都不動）。
   - 其他 driver（例如走 CLI 的傳輸）同樣只取不寫。
2. **本機狀態用覆蓋層**：已讀／星號／資料夾／封存／刪除全部記在本機（`mailops` 的 `mail_state` 這類表），重新同步也不會被蓋掉。
3. **憑證只從環境變數讀**：`accounts.json` 只放變數名稱（`password_env`）或走預設命名規則；設定檔裡出現明文密碼就**直接拒絕**。
4. API 只回「變數名稱」與「同步結果」，不回任何憑證內容；錯誤訊息要遮罩。
5. 提供 `POST /api/providers/check` 這種「只登入＋EXAMINE」的連線測試，讓使用者能在不匯入任何東西的情況下確認設定。
6. 每個帳號的同步結果記在 `LAST_SYNC`，`GET /api/providers` 顯示每帳號的信件數、未讀數、缺憑證提示與上次錯誤。
7. **測試用本機假伺服器**（`tests/_tpi_imap_fake.py`），並斷言指令序列裡沒有 `STORE`／`EXPUNGE`／`SELECT` 這類會改狀態的操作。

## 取捨

**我們放棄**

- 在伺服器端操作信件（批次已讀、搬移、刪除）——這些在本機模擬。
- 「一個設定檔帶著所有東西」的便利（憑證刻意不在檔案裡）。

**我們得到**

- 接了真信箱也不會弄壞它；使用者可以隨時收回權限而不擔心殘留狀態。
- 憑證不會出現在 repo、備份、截圖或日誌。

**已知代價**

- 本機狀態與伺服器狀態可能不一致（這是設計，不是 bug）。
- 使用者要自己設環境變數（文件已寫，且不示範把值寫進檔案）。

## 後果

- 新增任何 driver：必須唯讀、憑證只從環境讀、錯誤訊息遮罩、附假伺服器測試。
- 不要在日誌、API 回應、UI 提示或測試快照裡出現憑證值；測試需要假值時用明顯的假字串（例如 `FAKE_VALUE_FOR_TEST`）。
- 需要「寫回信箱」的提案，必須先開新 ADR，說明預設關閉、人工確認、以及如何避免影響真實信箱。
