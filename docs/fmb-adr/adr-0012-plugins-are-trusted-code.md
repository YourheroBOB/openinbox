# ADR-0012：外掛是受信任的本機程式碼，不是沙箱

- 狀態：已接受（現況仍有效）
- 日期：事後補建（原始決策日未記錄）
- 影響範圍：`server/features/`、`ui/modules/`、`GET /api/features`、文件
- 相關：ADR-0002、ADR-0007；ROADMAP 第 10 項

## 背景

自動註冊（ADR-0002）代表啟動時會 `import` `server/features/` 下的每個 Python 檔。這帶來
擴充性，也帶來一個必須講清楚的問題：這些程式碼與主程式**同行程、同權限**。若把外plug-in
描述成「安全沙箱」，使用者會做出錯誤的信任判斷。

## 決策

1. **明文定位**：Python 功能檔屬於受信任本機程式碼，不宣稱、不假裝是沙箱。
2. 壞外plug-in不拖垮全域：匯入失敗會被記錄，並在 `GET /api/features` 顯示健康狀態、路由與
   錯誤；錯誤訊息不含完整內部路徑或郵件內容（ADR-0014）。
3. 治理靠文件與 review，不靠隔離：外plug-in可讀取同行程可讀的本機檔案，使用者安裝前應自行審查。
4. UI 模組同樣是受信任程式碼，但其輸出仍受 ADR-0011 的轉義與 sandbox 約束。
5. 未來的版本治理、停用損壞外plug-in、相容矩陣排入 ROADMAP 第 10 項，不在本 ADR 承諾。

## 取捨

| 考慮過的做法 | 為什麼沒有選 |
|---|---|
| 子程序／容器隔離 | IPC 複雜度與啟動成本遠高於單機工具的收益 |
| 外掛簽章與允許清單 | 需要金鑰基礎設施；列為 ROADMAP 決策閘門選項 |
| 限制外掛可用 API | 削減擴充性，且仍不構成安全邊界 |

## 後果

**正面**

- 擴充成本極低：丟檔即用，不需要打包、簽章或程序管理。
- 信任邊界誠實，文件與安全審查不會互相矛盾。

**負面／代價**

- 安裝第三方外plug-in等於給予本機程式權限；需要持續在 README／ADR 提醒。
- 啟動期 import 錯誤可達，必須靠 `/api/features` 與 smoke 測試及早發現。
