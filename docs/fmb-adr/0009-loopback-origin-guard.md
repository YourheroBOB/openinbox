# ADR 0009：寫入端點的本機 Origin 防護

- 狀態：已接受（回溯整理）
- 相關程式：`server/features/_origin.py`（`local_origin`／`refuse`）、各 feature 的寫入端點、`server/features/calendar.py`（ICS 匯入的 `allow_private`）

## 背景

伺服器只聽 loopback（ADR 0001），但這**不代表安全**：使用者瀏覽器裡任何一個網站，都可以對 `127.0.0.1` 發出請求。
沒有防護的話，惡意頁面可以叫這個工具改狀態（標記、封存、產生草稿），甚至叫它去抓內網資源。

## 決策

1. 所有**有副作用**或**會讓伺服器主動連外**的端點，第一件事就是檢查本機來源：
   - 接受「沒有 `Origin`」的請求（curl、CLI、測試、MCP 這類非瀏覽器路徑）。
   - 接受 loopback 來源（`http://127.0.0.1:<任意本機埠>`、`http://localhost:<…>`）。
   - 其他一律拒絕（雙語錯誤訊息）。
2. 讀取端點同樣在敏感功能上加這個檢查，寧可嚴格。
3. 「會連外」的功能另外加限制：例如匯入同事行事曆（ICS）時，必須額外勾選之類的明確允許，才能連私有位址；同時限制大小、處理重新導向與迴圈、不洩漏標為私密的事件標題。
4. 這些檢查要**有測試**：外來 `Origin`（含 `text/plain` 這類簡單請求）必須被拒，且被拒時外部主機零命中。

## 取捨

**我們放棄**

- 「有登入就安全」的錯覺：這個工具沒有帳號系統，靠的是 loopback + Origin。
- 對非瀏覽器客戶端的細緻授權（本機程式本來就能讀檔案，沒必要假裝擋得住）。

**我們得到**

- 瀏覽器跨站請求打不進來；CSRF 面大幅縮小。
- 自動化（curl／測試／MCP）不需要額外憑證就能用，維持可測試性。

**已知代價**

- 每次新增寫入端點都要記得加一行檢查；漏掉不會有編譯錯誤，只會有安全破口（所以要有審查習慣與測試）。
- 少數合法但帶 `Origin` 的本機工具會被拒（可用 curl 繞過，屬於可接受的不便）。

## 後果

- PR 檢查清單：**每個 `@post` 都問一次「這會不會改狀態或連外？有 `local_origin` 嗎？」**
- 需要放寬時，只能針對特定端點、寫明理由、加測試，不要改動共用的檢查函式。
- 相關測試不得連外網；用本機起一條暫時的 HTTP 服務或直接餵檔案。
