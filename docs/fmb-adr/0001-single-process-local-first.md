# ADR 0001：單一行程、本機優先、只聽 loopback

- 狀態：已接受（回溯整理）
- 相關程式：`install.sh`、`run.sh`、`server/app.py`、`README.md`（雲端主機一節）、`README.zh-Hant.md`

## 背景

這個專案要解決的是「信箱腦放在自己的機器上」：沒有託管模型、沒有點數表、沒有第三方伺服器代收信件。
使用者可能是筆電上的單一使用者，也可能是丟在雲端 Linux 主機上跑、再從本機連進去。
這兩種情境都要求：安裝步驟越少越好，而且**資料的邊界就是那顆硬碟**。

## 決策

1. **一個 python3 行程**同時提供 HTTP API 與面板靜態檔（`server/app.py`），由 `run.sh` 啟動。
2. **只綁 `127.0.0.1`**，預設埠 `8770`（可用 `OPENINBOX_PORT` 覆寫）。不開對外埠、不架反向代理、不寫任何部署設定檔。
3. 遠端主機情境**只用 SSH 本機轉發**（`ssh -N -L 8770:127.0.0.1:8770 …`），文件明確寫「主機防火牆不要放行這個埠」。
4. 所有狀態留在本機：設定檔（`accounts.json`、`agent.json`、`rules.json`）、`data/`（SQLite 與產出物）、`vault/`（人格與卡片）。
5. 前景執行；要常駐就交給使用者自己的 `tmux`／`screen`。程式本身不安裝服務、不寫 systemd／launchd。

## 取捨

**我們放棄**

- 多程序／多使用者的架構（沒有工作佇列、沒有共享快取、沒有水平擴充）。
- 容器化與一鍵雲端部署（也就沒有「部署設定」可以被誤用）。
- 前端 build step（沒有 bundler，瀏覽器直接吃 `ui/` 下的檔案）。

**我們得到**

- `./install.sh && ./run.sh` 就能開；零 pip、零外部服務。
- 可審計：使用者能自己看每個檔案，知道資料去了哪裡。
- 測試可以在暫存目錄裡起真正的伺服器（見 `tests/_tpi_server.py` 與各測試的暫存根目錄）。

**已知代價**

- 手機要用 SSH 通道才進得來（PWA 只是安裝體驗，不是對外服務，見 ADR 0012）。
- 單一使用者假設貫穿整個設計：沒有權限模型，靠 loopback 與 Origin 檢查擋（見 ADR 0009）。

## 後果

- 任何新功能必須能在**單一行程、只用標準函式庫**的前提下完成（ADR 0003）。
- 不可以引入背景執行緒／常駐 worker 當必要條件；需要「跑一段時間」的工作做成使用者主動觸發的批次（例如夜班腳本）。
- 只要出現「開新埠」「反向代理」「對外介面」，就是破壞性變更：必須新增 ADR 說明威脅模型與預設值。
- 文件與 PR 不得描述任何未預設開啟的對外路徑。
