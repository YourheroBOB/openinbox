# OpenInbox STRIDE 威脅模型

## 1. 文件定位

本文件以目前分支可見的 OpenInbox 程式碼、設定、測試與設計說明為基準，使用 STRIDE 建立威脅模型，涵蓋：

- 資產與資料分級
- 信任邊界
- 主要資料流
- 各威脅情境的可能性、影響與風險
- 現有緩解、控制缺口
- 建議修補優先順序與驗收條件

### 1.1 與既有安全文件的去重原則

`docs/fmb-security/` 應保留部署、設定與日常操作規範；本文件不重抄其操作步驟，僅記錄「威脅、資料流、控制有效性、殘餘風險及修補優先序」。同一控制項若同時存在於兩處，具體操作方式以 `docs/fmb-security/` 為準，風險判定與缺口則以本文件為準。

### 1.2 結論摘要

1. **預設的 demo 模式、local agent、僅監聽 loopback、沒有寄信傳輸路徑**，可顯著降低遠端攻擊與資料外洩風險。
2. 進入 live mail、使用外部 BYO agent、匯入遠端 ICS 或開放 MCP 呼叫後，主要風險由一般本機資料外洩，升級為以下四類：
   - 惡意郵件內容造成 prompt injection，誘導分類、摘要、研究或草稿產生錯誤結果。
   - 郵件、persona、第二大腦與近期往來被送到未受完全信任的外部 agent。
   - 外部郵件可觸發保留的 agent 別名或提及，進而造成非預期的 agent 呼叫、費用與本機檔案寫入。
   - 本機 API 缺乏可見的使用者身分與授權層；`Origin` 檢查不是身分驗證，也無法防禦同主機程序。
3. 目前最優先的缺口為：
   - 所有 API 的一致性驗證、CSRF 與 Host 檢查。
   - 外部 agent 的資料外送政策、最小化與明確同意。
   - 禁止不可信郵件自動觸發具外部資料能力的 agent。
   - 呼叫次數、並行數、內容大小與費用預算。
   - 全域輸出編碼、CSP 與瀏覽器 DOM 注入防護。
4. **強烈建議**：在完成 P0 項目前，不將 OpenInbox 當成多人主機服務，也不把 live 郵件與外部 agent 同時開啟。

## 2. 範圍、假設與限制

### 2.1 分析範圍

包含：

- `server/app.py`、`server/yhbmail.py` 與 `server/features/`
- 靜態面板與 PWA
- MCP stdio 工具
- Gmail／Outlook 外部 CLI、IMAP 連線
- OpenAI 相容端點、CLI agent、HTTP worker
- 行事曆與 ICS feed
- 本機 SQLite、檔案快取、vault、contacts、草稿、outbox、成果卡片
- `scripts/overnight.py` 與自動規則
- 本機設定檔與外部執行檔

不包含：

- 作業系統 root、實體主機失竊與同使用者帳號遭完整控制後的 取證能力。
- 郵件服務商、模型服務商或外部 agent 內部未被本專案控制的安全缺失。
- 未啟用的寄信功能；但若未來加入寄信傳輸，必須另做一次端到端威脅模型。
- 純粹模型內容品質或事實正確性問題；與資料外送、工具權限有關的風險仍在範圍內。

### 2.2 關鍵假設

| 編號 | 假設 | 影響 |
|---|---|---|
| A-01 | 預設部署是單一使用者、單機或個人雲端主機。 | 若改為多人共享，無認證的本機 API 會立即成為高風險缺口。 |
| A-02 | 伺服器只應綁定 loopback，遠端使用 SSH tunnel。 | 不得將目前設計誤當成可公開存取的 Web 服務。 |
| A-03 | 收到的郵件主旨、內文、寄件人欄位、附件與 ICS 內容全部不可信。 | 即使來自真實供應商，也不能假設內容無害。 |
| A-04 | `agent.json` 指向的外部端點、CLI 與 HTTP worker 不由本專案控制。 | 這些元件可讀取 context pack、回傳不可信內容，且可能成為資料外送點。 |
| A-05 | 設定檔、程式碼與本機資料目錄由同一 OS 帳號擁有。 | 同一帳號的惡意程式可破壞完整性；加密不能取代權限隔離。 |
| A-06 | 未啟用寄信傳輸，草稿與 outbox 僅留在本機。 | 現階段資料竄改不會直接造成對外寄送。 |
| A-07 | 預設為 demo 與 local agent。 | 外部資料流風險在切換 live 或遠端 agent 後才大幅上升。 |

### 2.3 證據分級

- **程式碼確認**：可直接由目前提供的程式碼確認。
- **設計宣稱**：README 或狀態文件明載，但本文件未將其視為完整安全驗證。
- **待稽核**：需對所有路由、UI 模組與序列化路徑做完整檢查才能確認。

## 3. 風險評估方法

### 3.1 可能性

| 等級 | 定義 |
|---|---|
| 低 | 需要管理員權限、實體接近或非常規設定；一般遠端攻擊者難以獨立達成。 |
| 中 | 需要 live mode、常見本機惡意程式、特定使用者操作，或可由網路輸入觸發。 |
| 高 | 在合理部署或正常使用下可經常發生，或不需要額外高權限即可觸發。 |

### 3.2 影響

| 等級 | 定義 |
|---|---|
| 低 | 單一暫時功能錯誤，無機密外洩或持久資料破壞。 |
| 中 | 單一功能的資料不完整、可回復的服務中斷或有限診斷資訊外洩。 |
| 高 | 大量受限郵件／行事曆資料外洩、草稿或本機狀態遭誤改、成本增加。 |
| 重大 | 憑證或全量受限資料外洩、遠端程式執行、跨邊界存取或重大完整性破壞。 |

### 3.3 修補優先序

| 優先序 | 定義 |
|---|---|
| P0 | 進入 live mode、使用外部 agent 或對外提供服務前必須完成。 |
| P1 | 下一個安全里程碑完成；處理高影響的完整性、隔離與稽核缺口。 |
| P2 | 近期改善，降低機率、資料保留與可用性風險。 |
| P3 | 預防性強化與自動化，不直接阻擋目前的上線條件。 |

可能性與影響分數需合併判讀；例如低機率但重大影響的設定注入仍可列為 P1。

## 4. 資產

| ID | 資產 | 分級 | 主要位置 | 安全目標 | 失效後果 |
|---|---|---|---|---|---|
| A-01 | 郵件內容與中繼資料 | 受限 | 本機 SQLite、快取、搜尋索引 | 保密性、完整性、可清除性 | 私人通訊、關係與待辦事項外洩或遭誤改。 |
| A-02 | 附件與附件衍生資訊 | 受限 | 快取、附件處理路徑 | 保密性、完整性、資源限制 | 惡意檔案或大型內容造成洩漏、佔用資源或解析風險。 |
| A-03 | 草稿、附件草稿與 outbox | 受限 | SQLite、`data/` | 保密性、來源可追溯性、不可誤寄 | 草稿被改寫或誤認成使用者決策；未來若加入寄信，將提高為重大風險。 |
| A-04 | 帳號、provider 與 agent 設定 | 內部／敏感 | `accounts.json`、`agent.json` | 完整性、擁有者限定 | 可改變資料流目的地、服務商或執行行為。 |
| A-05 | IMAP、模型或其他服務憑證 | 機密 | 程序環境變數 | 機密性、最小暴露 | 外部服務遭未授權存取。 |
| A-06 | persona、第二大腦、CRM、偏好與修正是 | 受限 | `vault/`、本機資料檔 | 保密性、完整性、來源可追溯 | 可推斷使用者身分、習慣與關係，並被用於誘導 agent。 |
| A-07 | 行事曆、free/busy、ICS feed | 受限 | SQLite、ICS 設定與快取 | 保密性、完整性 | 行程與空檔資訊外洩或遭誤導。 |
| A-08 | Agent 產物、摘要、卡片、投影片與 brief | 受限 | `data/`、`vault/` | 完整性、保密性、隔離 | 惡意或錯誤輸出被當成正式成果；內容可能持續留存。 |
| A-09 | 搜尋索引、任務、規則與用量紀錄 | 受限／內部 | SQLite、`data/` | 完整性、最低蒐集 | 資料殘留、錯誤自動動作或無法追查操作。 |
| A-10 | 程式碼、外掛、設定與外部執行檔 | 完整性關鍵 | repository、Python 模組、設定檔 | 完整性、可審核性 | 啟動時即可取得伺服器程序權限。 |
| A-11 | 本機 API 與 MCP 工具能力 | 權限關鍵 | 路由與工具登錄 | 最小權限、明確授權 | 未授權讀寫郵件、建立草稿或修改本機狀態。 |
| A-12 | 服務可用性與外部呼叫預算 | 運維關鍵 | 同步、agent、搜尋、背景工作 | 可用性、有限資源 | 郵件同步停擺、呼叫暴增或成本失控。 |
| A-13 | 稽核與來源紀錄 | 內部 | 目前多數為一般應用紀錄 | 可追溯、不可竄改 | 無法回答「誰在何時以何種輸入產生哪個動作」。 |

## 5. 參與者與攻擊者

| 參與者 | 信任狀態 | 可觀察或可影響的內容 |
|---|---|---|
| 機主／操作者 | 高信任 | 設定檔、資料、UI 操作、agent 選擇。 |
| 本機瀏覽器與面板 | 部分信任 | 讀取 API 回應、發動變更；頁面中的郵件內容不可信。 |
| 同主機其他程序或使用者 | 不信任 | 可嘗試連線 loopback、讀寫檔案、取得環境或影響 PATH。 |
| 遠端郵件寄件者 | 不信任 | 可控制主旨、內文、寄件人欄位、附件與觸發條件。 |
| 郵件服務商與外部 CLI | 條件信任 | 傳輸資料、錯誤訊息、OAuth 狀態與命令列行為。 |
| 外部模型／agent／worker | 不信任或條件信任 | 接收 context pack，回傳可執行文字、摘要或研究內容。 |
| MCP 客戶端 | 高權限但僅能信任到程序邊界 | 可列工具、讀本機資料、建立草稿。 |
| 行事曆 feed 伺服器 | 不信任 | 控制 ICS 內容、更新頻率、重新導向與網路目的地。 |
| 套件管理、安裝流程與相依套件 | 供應鏈邊界 | 可改變程式、外部命令或設定解析行為。 |

## 6. 信任邊界

| ID | 邊界 | 跨越資料 | 判斷 |
|---|---|---|---|
| TB-01 | 瀏覽器／面板 ↔ 本機 HTTP API | 郵件內容、命令、設定與草稿 | 同一來源可降低 CSRF 風險，但不能取代驗證、授權與 Host 檢查。 |
| TB-02 | 伺服器程序 ↔ 本機檔案系統 | SQLite、設定、vault、產物、簽章與匯入檔 | 檔案完整性與 OS 權限是主要控制；資料本身可能不可信。 |
| TB-03 | OpenInbox ↔ 郵件供應商／外部 CLI | 憑證、收件匣資料、同步結果 | 供應商傳回的內容一律視為不可信；CLI 本身也是外部執行邊界。 |
| TB-04 | OpenInbox ↔ BYO agent／模型端點 | persona、brain、近期郵件、搜尋結果與任務要求 | 這是最重要的資料外送邊界；端點選擇等同資料流向選擇。 |
| TB-05 | OpenInbox ↔ 行事曆 feed | URL、ICS 內容與解析結果 | 同時涉及資料完整性與 SSRF；不能只依賴字串檢查。 |
| TB-06 | MCP 客戶端 ↔ stdio MCP 程序 | 工具查詢、回應、搜尋輸入與草稿寫入 | 程序邊界即權限邊界；stdio 不等於呼叫者已獲最小權限。 |
| TB-07 | OpenInbox ↔ CLI agent／外部 helper | context pack、環境變數、命令列參數 | 設定可執行任意命令是管理員能力，也是設定被竄改後的提升路徑。 |
| TB-08 | 瀏覽器 ↔ Service Worker／瀏覽器儲存 | 靜態程式碼與少量離線資源 | API 應保持不落地；頁面 DOM、歷史、剪貼簿與螢幕仍是資料外洩面。 |
| TB-09 | 個人主機 ↔ 雲端主機／SSH tunnel | 全部本機 API 能力 | loopback 只保護網路暴露，不保護主機上的其他帳號或程序。 |
| TB-10 | repository ↔ 外掛、啟動腳本與相依套件 | 程式碼與設定 | 能修改 repository 的主體已接近伺服器程式執行權限。 |

## 7. 資料流

| ID | 來源 → 目的 | 資料與分級 | 目前邊界控制 | 主要風險 |
|---|---|---|---|---|
| DF-01 | 設定／環境變數 → 郵件或 agent 連線器 | 機密憑證、端點、帳號設定 | 憑證以環境變數為主；部分設定拒絕明文密碼 | 設定被竄改、程序環境被子程序繼承、端點誤設。 |
| DF-02 | 郵件供應商／CLI → 本機快取 | 郵件、寄件人、收件人、主旨、內文、附件 | 支援唯讀連線、快取位於本機 | 惡意內容、資源耗用量、供應商資料一致性與凭證揭露。 |
| DF-03 | 本機快取 → HTTP API → 瀏覽器 | 受限郵件與衍生資料 | loopback、部分路由檢查本機來源 | 無認證讀取、跨來源攻擊、DOM 注入。 |
| DF-04 | UI／API → 搜尋、分類、摘要、agent | 使用者指示與不可信郵件內容 | 部分流程有長度上限與 quoted-data 規則 | Prompt injection、資料誤分類、工具濫用。 |
| DF-05 | 本機資料 → 外部 agent／模型 | persona、brain、近期郵件、搜尋與來源摘錄 | local driver 預設；remote driver 需使用者設定 | 廣泛資料外送、供應商留存、跨租戶混用。 |
| DF-06 | 外部 agent／CLI → 摘要、草稿、卡片、brief | 模型產生的不可信文字 | 產物限制於本機；成果 HTML 會跳脫並在 sandbox iframe 顯示 | 惡意或錯誤輸出被當成事實；後續再被其他流程處理。 |
| DF-07 | UI／API → SQLite、vault、`data/` | 草稿、任務、規則、卡片、CRM、outbox | 部分寫入端點檢查本機來源；資料目錄被 gitignore | 未授權變更、路徑／symlink 問題、資料殘留。 |
| DF-08 | MCP 客戶端 → 本機工具 → 快取／草稿 | 收件匣列表、brain、persona、搜尋輸入 | stdio、有限工具集、`save_draft` 不寄出 | 呼叫者無細緻授權、讀取大量資料、建立非預期草稿。 |
| DF-09 | 遠端 ICS URL／檔案 → 解析器 → 行事曆快取 | 行程、空檔、摘要與 feed 設定 | 有大小上限與私有位址選項；CLASS 資料有隱私處理 | SSRF、DNS rebinding、惡意 ICS、行程誤導。 |
| DF-10 | 郵件規則／overnight → 分類、標籤、歸檔、草稿、brief | 郵件欄位、規則條件與模型輸出 | 預設 dry-run；草稿與 brief 留在本機 | 規則或 prompt injection 觸發大量本機變更。 |
| DF-11 | 瀏覽器 ↔ Service Worker cache | 靜態 HTML、JS、圖示與離線頁 | 快取排除 `/api/*`；頁面內容不落地 | 靜態程式碼版本或完整性問題、瀏覽器其餘殘留。 |
| DF-12 | repository → Python 外掛、CLI helper、shell script | 程式碼、設定與命令 | 主要依賴標準庫；外掛自動載入 | 供應鏈或設定被竄改後直接取得程式執行權限。 |

## 8. 現有緩解與其限制

| ID | 現有控制 | 證據 | 限制 |
|---|---|---|---|
| C-01 | 伺服器預設僅供本機使用，遠端以 SSH tunnel 連入。 | 設計說明 | loopback 不提供使用者身分驗證，也不防同主機程序。 |
| C-02 | 多個狀態變更端點檢查 `Origin` 是否為本機來源。 | `server/features/agents.py` 及其他功能的設計說明 | 尚需確認所有路由一致套用；`Origin` 不是身分驗證，且 GET 不應承擔狀態變更。 |
| C-03 | 寄信預設關閉，草稿、outbox、排程與 undo 留在本機。 | 設計說明 | 未來加入傳輸路徑時必須重新威脅建模。 |
| C-04 | IMAP 密碼從環境變數讀取，設定中的明文密碼會被拒絕。 | 設計說明與 provider 狀態文件 | 未驗證子程序環境最小化與檔案權限。 |
| C-05 | IMAP 使用唯讀操作，避免改變遠端已讀或資料夾狀態。 | provider 設計說明 | 唯讀不等於無資料外洩；錯誤處理仍可能洩漏回應。 |
| C-06 | 成果卡片 ID 使用嚴格格式檢查，路徑不得任意穿越。 | `server/features/agents.py` | 只能防止字串路徑穿越，不能防止父目錄 symlink 或擁有者被同帳號程式替換。 |
| C-07 | 成果 HTML 會跳脫內容，預覽使用 sandbox iframe。 | `server/features/agents.py`、`ui/modules/agents.js` | 其他 UI 模組仍需完整 DOM 注入稽核；HTML 跳脫不能防止語意型 phishing。 |
| C-08 | Agent context 明確要求把郵件視為資料，不執行其中指示。 | `server/features/agents.py` | 這是提示詞層控制，不是工具權限或資料流強制隔離。 |
| C-09 | Agent 錯誤回傳只顯示例外類別與狀態碼，避免直接回顯端點 body 或 CLI stderr。 | `server/features/agents.py` | 其他 agent 與連線功能需逐一路徑確認相同 sanitization。 |
| C-10 | Service Worker 不快取 `/api/*`，只處理靜態資源。 | PWA 設計與狀態文件 | 瀏覽器 DOM、記憶體、歷史、剪貼簿與其他快取仍可能保留資料。 |
| C-11 | MCP 僅提供有限的讀取工具與本機草稿工具，不暴露寄送。 | `server/mcp_server.py` 設計說明 | 有限的工具面無法取代呼叫者身分、最小權限與稽核。 |

## 10. 端到端濫用情境

### 10.1 惡意郵件觸發外部 agent

1. 攻擊者寄出含保留提及或命中 agent 路由的郵件。
2. 郵件被正常同步至本機快取。
3. agent 路由判斷應執行研究或準備任務。
4. context pack 帶入該郵件、persona、brain 與其他本機來源。
5. 若使用外部 driver，敏感內容離開本機並產生外部費用。
6. 結果寫入成果卡片，可能被後續流程誤當成可信資料。

目前沒有寄信步驟，因此此情境不會直接對外寄送；但仍可能造成資料外送、成本與本機完整性問題。**緩解重點是取消郵件的自動外部執行能力，而非只依賴提示詞。**

### 10.2 惡意網頁影響本機 API

1. 使用者在應用程式執行期間瀏覽攻擊者網站。
2. 攻擊者利用跨來源請求、Host 驗證缺口、DNS rebinding 或不當的 GET 副作用。
3. 惡意請求讀取本機狀態，或建立草稿、修改事件、觸發 agent。
4. 若瀏覽器存在 DOM 注入，攻擊者還可借用受害者瀏覽器的同來源能力。

此情境不需直接存取主機檔案，故應以全域 session、來源與 Host 驗證優先處理。

### 10.3 設定檔遭竄改後redirect資料流

1. 惡意程式取得 `agent.json` 或 `accounts.json` 寫入權限。
2. 將外部端點改成攻擊者網域，或把 CLI driver 改成任意命令。
3. 下一次摘要、搜尋改寫或研究操作將資料送到新目的地，或執行命令。
4. 若沒有設定變更稽核，使用者很難知道資料流已改變。

### 10.4 郵件洪水造成費用與可用性下降

1. 大量郵件進入快取，部分符合自動規則或 agent 觸發條件。
2. 每封信都呼叫外部 agent，沒有全域預算與 rate limit。
3. 外部端點延遲造成請求堆積，磁碟同時增加大量成果。
4. UI 與同步工作被背景工作佔用。

### 10.5 行事曆 feed 的 SSRF

1. 操作者或被誘導的使用者加入遠端 feed。
2. feed 重新導向、解析後 DNS 或 IPv6 位址指向內部服務。
3. 伺服器代替操作者探測內部端點，回應差異可能暴露服務存在性。
4. 若允許私有位址，風險由資訊洩漏提升至內部資料存取。

## 12. 建議修補優先順序

### 12.1 P0：live／外部 agent 上線前阻斷項

#### P0-1：建立統一 API 存取邊界

建議內容：

- 每次安裝產生高熵 session credential，由面板透過受保護的同來源方式取得，不放入 URL、log 或錯誤訊息。
- 所有 API 讀取與寫入都要求有效 session；健康檢查與靜態資產可保留最小例外。
- 僅允許 `127.0.0.1`、`localhost` 與實際本機 port 的 Host；拒絕其他 Host。
- 所有狀態變更僅接受 POST／PATCH／DELETE 類方法，並同時驗證 session、來源與內容型別。
- 將讀取、產生草稿、修改設定、觸發 agent、清除資料分成不同 scope。
- 對錯誤回應與稽核記錄移除 session 與敏感欄位。

驗收條件：

- 未驗證的讀取與寫入請求均被拒絕。
- 跨來源、偽造 Host 與不允許方法無法改變資料。
- 測試僅使用本機假 server 與暫存目錄，不連正式服務。

#### P0-2：外部 agent 資料外送閘門

建議內容：

- 預設目的地只能是本機；外部目的地需逐項 allowlist 與明確啟用。
- 強制 HTTPS；拒絕不明重新導向與私有位址。
- 將 context 拆成可勾選的 profile，例如只含任務、最近 N 筆信件、搜尋結果、persona、calendar。
- UI 顯示目的地與將傳送的欄位類型，不顯示敏感內容。
- 對每次外送記錄 principal、目的地、profile、來源 ID 與數量，不記錄完整內容。
- 不允許郵件內容決定目的地、模型參數、工具權限或設定。

驗收條件：

- 未 allowlist 的端點無法收到 context。
- 在 context 中放入要求忽略規則的測試文字，不會改變目的地、scope 或工具能力。
- 傳送記錄可追查，但不包含郵件內文。

#### P0-3：取消不可信郵件的自動 agent 執行

建議內容：

- 郵件同步只產生待處理項目，不直接呼叫 agent。
- 保留提及只能產生建議或待確認工作；操作者按鈕確認後才執行。
- 若保留自動模式，至少要求來源 allowlist、每日次數上限、單一郵件只處理一次，且不得帶入 persona 或其他信件。
- 對高影響輸出只產生草稿或建議，不直接套用分類、歸檔、CRM 或行事曆。

驗收條件：

- 任意遠端郵件不能自行造成外部 agent 呼叫。
- 重複郵件與重試不會突破呼叫預算。
- 自動化規則預設仍為 dry-run。

#### P0-4：全域資源與費用預算

建議內容：

- 對同步、搜尋、agent、翻譯、摘要、ICS 與附件處理設定大小上限。
- 對 agent 設定每分鐘、每日、最大並行與最大產物數。
- 對外部端點設定總 timeout、有限重試與熔斷。
- 對 regex、FTS、JSON 與 ICS 設定計算量上限。
- 達到預算時明確顯示原因並停止昂貴操作，不得無限退避。

驗收條件：

- 大量輸入在固定時間與記憶體範圍內失敗。
- 逾時端點不會留下無限排隊程序或重試迴圈。
- 達到每日預算後不再呼叫外部服務。

#### P0-5：瀏覽器輸出防護

建議內容：

- 對所有 UI 模組建立 DOM sink 清單，逐項確認郵件主旨、內文、錯誤與模型產物均以文字或安全編碼輸出。
- 設定嚴格 CSP，限制 script、style、frame 與 connect 的來源；框架使用必要時保留 sandbox。
- 禁止 inline event handler 與未經驗證的 HTML。
- 對郵件、搜尋結果、agent 結果、錯誤、列印頁與列印預覽建立負向測試。

驗收條件：

- 惡意標記不會形成可執行 DOM。
- UI 仍能在本機正常運作，且不依賴外部 CDN。

### 12.2 P1：下一安全里程碑

1. **檔案系統與設定完整性**
   - 資料目錄與設定採擁有者專用權限。
   - 啟動時檢查 symlink、擁有者、權限與外掛清單。
   - 對設定採 atomic write 與版本記錄。
   - 對外部命令採最小環境與非 shell 執行。

2. **統一 SSRF／egress policy**
   - 共用 URL 正規化、DNS 解析、重新導向與位址分類。
   - 套用於 ICS、IMAP、HTTP agent 與所有未來網路功能。
   - 對私有位址與本機服務採明確 deny／allow 決策。

3. **資料保留與清除**
   - 建立完整資料資產清單，涵蓋 DB、索引、persona、contacts、cards、deliverables、briefs、slides、usage 與 outbox。
   - 原始郵件與衍生資料採可設定的有限保留期；使用者手寫卡片與未送出草稿不應在未告知下刪除。
   - 提供清除結果摘要，讓操作者知道哪些資料已刪除、哪些因用途而保留。

4. **稽核與來源追蹤**
   - 記錄 principal、action、resource type、result 與 correlation ID。
   - 不記錄完整郵件、context、模型輸出或憑證。
   - 草稿與未來 outbox 保留版本、來源與人工確認紀錄。

5. **MCP 最小權限**
   - 區分唯讀與可寫 session；限制單次讀取筆數與搜尋範圍。
   - MCP 草稿寫入與 UI 草稿使用相同來源標記與撤銷機制。
   - 不允許 MCP 改變 agent 目的地、帳號設定或全域規則。

6. **SQLite 與背景工作**
   - 設定 busy timeout 與短交易。
   - 索引重建、brief 與大量匯入移出前景請求。
   - 以程序鎖或工作佇列避免多個 overnight 同時執行。

### 12.3 P2：近期強化

- Service Worker 原子更新、版本與資產 hash 驗證。
- 更完整的資料保留與磁碟加密選項。
- 瀏覽器工作階段清除、通知預覽控制與剪貼簿最小化。
- 對外部錯誤、URL、郵件欄位與 hostname 做中央 redaction。
- 更細的 ICS 展開、事件數與欄位限制。

### 12.4 P3：預防性強化

- 自動化的 route matrix：逐一驗證方法、認證、來源、scope 與副作用。
- 週期性 threat-model drift review：每次新增外部端點、工具、傳輸路徑時更新 DFD。
- 定期以隔離的本機假服務執行安全回歸測試。
- 對 repository、外掛與靜態資產建立完整性基線。

## 13. 建議驗證計畫

所有測試應遵守：

- 只使用 `tempfile` 或測試框架的暫存目錄。
- 不連線到正式郵件、模型、日曆或其他線上服務。
- 需要假憑證時使用 `FAKE_VALUE_FOR_TEST`。
- 不在輸出、log 或 fixture 中保存真實或近似真實的憑證。
- 不複製真實郵件內容或個人資料。

### 13.1 路由與存取控制

- 列出所有 GET／POST／PATCH／DELETE 路由，標示是否會改變狀態。
- 驗證未認證、錯誤 Host、跨來源與不允許方法。
- 驗證不同 scope 不能互相取得權限。
- 驗證 GET 路由沒有隱含同步、刪除、寄送或外部呼叫副作用。

### 13.2 Agent 與資料外送

- 使用本機 fake agent server 驗證目的地 allowlist、TLS 檢查與重新導向政策。
- 驗證 persona、近期郵件與搜尋結果不會超出所選 context profile。
- 以包含命令式文字的假郵件測試 prompt injection，確認不會改變工具權限、目的地或造成非預期寫入。
- 驗證呼叫率、並行、總 timeout、每日預算與熔斷。

### 13.3 檔案與路徑

- 在暫存目錄建立 symlink、特殊檔案與錯誤擁有者情境。
- 驗證成果、匯入、匯出、contacts、brief 與 slides 不會寫出允許根目錄。
- 驗證檔案採 atomic write，且失敗不會留下部分資料。
- 驗證資料目錄與設定檔權限不符合預期時，服務拒絕啟動或只以唯讀模式啟動。

### 13.4 瀏覽器與 Service Worker

- 對所有顯示郵件與模型輸出的頁面執行 DOM 注入負向測試。
- 驗證 CSP 生效，且 API 回應不進 Cache Storage。
- 驗證版本更新時舊 worker 不會長時間控制頁面。
- 驗證列印頁與 sandbox iframe 不允許 script、form、navigation 或外部資源。

### 13.5 現有回歸

文件變更本身不應影響既有功能；實作安全修補後，應執行：

```bash
python3 -m unittest discover -s tests
scripts/smoke.sh
```

並額外執行新增的安全回歸測試。所有正式整合測試仍應使用本機假服務。

## 14. 保守政策與決策

### 14.1 建議採用的保守預設

1. **部署模型**：只支援單一擁有者、loopback 與個人 SSH tunnel；不把未認證的本機 API 公開到網路。
2. **Agent 模式**：預設僅 local。外部目的地採逐項 allowlist，並要求使用者明確同意資料範圍。
3. **郵件觸發**：遠端郵件只能建立建議或待確認工作，不可自動呼叫具有外部資料能力的 agent。
4. **MCP**：視為本機高權限 client；唯讀與草稿寫入分開授權，所有寫入可稽核。
5. **資料保留**：原始郵件與模型衍生快取採有限預設保留期；草稿與使用者手寫內容不自動刪除。
6. **傳輸功能**：維持不寄信；若加入任何實際寄送路徑，必須停止使用本模型作上線依據，重新建立完整 threat model。

### 14.2 需要產品所有者確認的營運決策

以下項目不阻礙威脅模型成立，但會影響實作方案：

- 是否允許 live mode 同時使用外部 agent；若允許，應逐目的地核准。
- 遠端 agent 可取得的 context profile 與預設保留期。
- 原始郵件、快取、成果、contacts 與草稿各自的保留期限。
- 是否支援共享或多人主機；若支援，session 與角色權限必須升級為 P0 的多人設計。
- MCP 是否需要多人或跨機器使用；若是，stdio 邊界不足，需重新設計驗證與傳輸。

## 15. 殘餘風險與模型重審條件

即使完成本文件建議，仍存在下列殘餘風險：

- 取得同一 OS 帳號的惡意程式可能讀取未加密資料或竄改程式。
- 外部 agent 或模型供應商可能超出 OpenInbox 控制範圍地保留或錯誤使用 context。
- 自動分類與摘要仍可能有語意錯誤；人工確認不能保證正確，只能降低風險。
- 實體裝置遭扣押時，磁碟未加密可能造成資料外洩。
- 供應鏈遭入侵時，程式碼完整性控制仍可能被繞過。

出現以下任一變更時，必須重做威脅模型：

- 加入真正的寄信、收信回執或 webhook。
- 新增公開網路監聽、反向代理或多人帳號。
- 新增可執行外掛、動態模型、瀏覽器擴充功能或第三方 marketplace。
- 外部 agent 獲得 shell、檔案系統、CRM 或行事曆寫入權限。
- MCP 改為 TCP／HTTP、跨機器或多人共用。
- 快取移至雲端資料庫或共享儲存。

完成後應更新本文件的資產、資料流、STRIDE 情境與優先序，並保留版本差異。
